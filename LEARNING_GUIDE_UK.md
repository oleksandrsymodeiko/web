## Як читати цей розбір

Статус **«так»** означає, що основний результат і перевірені пункти модуля є в проєкті. **«Частково»** означає, що результат є, але конкретні пункти чек-листа не виконано або їх неможливо перевірити наданими файлами. **«Ні»** означає, що ключового результату немає. Я не називаю відсутню публікацію чи демонстраційну форму готовим сайтом.

Проєкт у `web-course/` — одна HTML-сторінка. Браузер читає `index.html`, завантажує `css/style.css` і фотографію, будує сторінку, а після HTML виконує `js/main.js`. Класи пов'язують HTML зі стилями й скриптом: наприклад, `class="nav-toggle"` у HTML шукається селектором `.nav-toggle` у CSS і `document.querySelector('.nav-toggle')` у JS. Назви за схемою BEM: `plan` — блок, `plan__price` — його частина, `plan--featured` — варіант блоку.

## Модуль 1 — [проєктування у Figma](https://9.lviv.ua/academy/web-development/figma-design/)

**Висновок: частково.** Тема тренажерного залу й головна дія «записатися на пробне заняття» зрозумілі з першого екрана. У Figma є окремі desktop і mobile макети, дев'ять змістовних секцій, тематичне фото, логотип та іконки. Код використовує два сімейства шрифтів — Anton та Inter. На сайті немає Lorem ipsum. Проте урок прямо просить фрейми **Desktop 1440** і **Mobile 375**: наданий desktop-фрейм підписаний **Desktop — 1200**. Це різниця з навчальним чек-листом, а не доказ поганого макета.

| Пункт уроку | Що видно в матеріалах |
|---|---|
| Ніша, аудиторія, головна дія | Ніша й дія читаються; окремого опису аудиторії немає. |
| Аналіз 3–5 сайтів ніші | Нотаток/посилань у проєкті немає — не можна підтвердити. |
| Паперові ескізи двох ширин | Не надані — не можна підтвердити. |
| Два Figma-фрейми | Є; desktop 1200 замість названих у модулі 1440, mobile 375. |
| Щонайменше 5 блоків | Є дев'ять секцій від hero до footer. |
| Справжні тексти | Lorem ipsum немає, але адреса, телефон, ціни, тренери й відгуки — непідтверджені дані прототипу. |
| Тематичні фото, узгоджені іконки | Фото залу є; барбел/SVG і буквені бейджі в одному стриманому стилі. |
| До 3 кольорів, до 2 шрифтів | Два шрифти є; основа — темний, світлий, червоний, але CSS має також похідні відтінки й оливковий акцент. Буквальне «не більше трьох» не підтверджено. |
| Відступи кратні 8, зрозумілі шари | Основна шкала кратна 8; окремі дрібні значення — ні. Повний список шарів Figma через доступний перегляд не перевірений. |
| Перебудований mobile-макет і доступне посилання | Окремий вузький макет видно, посилання на Figma відкривається для перегляду. |

У коді дизайн виражений через токени, а не через випадкові кольори в кожному блоці:

```css
:root {
  --color-ink: #14140F;
  --color-paper: #F1EEE6;
  --color-red: #D62828;
  --font-display: 'Anton', 'Arial Narrow', sans-serif;
  --font-body: 'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
  --sp-1: 8px;
  --sp-2: 16px;
}
```

`--color-ink` називає роль кольору, тому той самий темний відтінок використовується в заголовках, темних секціях і логотипі. Якщо змінити токен, усі ці місця оновляться разом. `--font-display` призначений для коротких великих заголовків, `--font-body` — для довгого читання. Шрифти після коми — запасні, якщо локальний шрифт недоступний. `--sp-*` створює шкалу повторюваних відступів. **Що ще потрібно вам:** підтвердити реальні бізнес-дані й, якщо завдання оцінюють буквально, вирішити, чи потрібен desktop-фрейм саме 1440 px і нотатки з аналізу ніші.

## Модуль 2 — [HTML, CSS і Flexbox](https://9.lviv.ua/academy/web-development/html-css-flexbox/)

**Висновок: так щодо коду, з обмеженням щодо точних вимірів Figma.** Є структура `index.html`, `css/`, `img/`; повний HTML-каркас; семантичні `header`, `nav`, `main`, `section`, `article`, `footer`; окремий CSS без атрибутів `style`; глобальний `box-sizing`; змінні; Flexbox для меню, карткових рядів, тарифів, hero і контакту. Після цього допрацювання ряди карток також використовують Flexbox. Усі секції макета присутні.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="css/style.css">
</head>
<body>
  <header class="header">…</header>
  <main id="main">…</main>
  <footer class="footer">…</footer>
  <script src="js/main.js"></script>
</body>
</html>
```

`DOCTYPE` вмикає сучасний режим HTML. `lang="en"` правильний для англомовного вмісту сайту; мова цього пояснення не повинна змінювати мову сторінки. `charset` дозволяє коректно показувати символи на кшталт `&` і тире. `viewport` каже телефону використовувати свою реальну ширину. CSS підключено в `head`, щоб оформлення застосувалось під час побудови сторінки; JS стоїть перед `</body>`, коли елементи вже існують у DOM. `header/main/footer` дають програмам зчитування екрана орієнтири, яких не дає безіменний `div`.

```css
*, *::before, *::after { box-sizing: border-box; }
.container {
  max-width: var(--container-w);
  margin: 0 auto;
  padding: 0 var(--container-pad);
}
.programs__grid { display: flex; flex-wrap: wrap; gap: var(--sp-3); }
.programs__grid > * {
  flex: 0 1 calc((100% - 3 * var(--sp-3)) / 4);
  min-width: 0;
}
```

`border-box` включає padding і border у задану ширину — картка не стає несподівано ширшою. `max-width`, на відміну від `width: 1200px`, дозволяє контейнеру стискатися. `margin: 0 auto` центрує його. `flex-wrap: wrap` переносить картки на наступний ряд, `gap` задає відстань. Для чотирьох карток із трьома проміжками формула спочатку віднімає проміжки, тоді ділить залишок на чотири. `flex: 0 1 …` означає: не розтягувати самотню картку до ширини всього ряду, дозволити стискання, взяти обчислену ширину за основу. `min-width: 0` дозволяє довгому тексту не розпирати Flexbox.

**Не доведено повністю:** точні розміри й відступи з Figma Inspect; звірка в доступному перегляді була візуальною. Код показує desktop-дизайн, але статус «піксель у піксель» був би необґрунтованим.

## Модуль 3 — [адаптивність і бургер-меню](https://9.lviv.ua/academy/web-development/responsive-burger-menu/)

**Висновок: частково.** Медіа-запити на 1024, 768 і 480 px стоять після базових стилів. На планшеті картки стають по дві, на телефоні — по одній; тарифи й контакт переходять у стовпчик, кнопки hero заповнюють ширину. Меню приховане через `visibility: hidden`, тому закриті посилання не повинні потрапляти в Tab-порядок. Кнопка має `aria-expanded` і відкривається клавішею Space. JS закриває меню після вибору посилання, Escape, кліку зовні та розширення вікна.

```css
@media (max-width: 1024px) {
  .programs__grid > * { flex-basis: calc((100% - var(--sp-3)) / 2); }
}
@media (max-width: 768px) {
  .nav-toggle { display: inline-flex; }
  .nav { opacity: 0; visibility: hidden; }
  .nav.is-open { opacity: 1; visibility: visible; }
  .programs__grid > * { flex-basis: 100%; }
}
@media (max-width: 480px) {
  .hero__actions { flex-direction: column; }
  .hero__actions .btn { width: 100%; }
}
```

Медіа-запит спрацьовує тільки до вказаної ширини. Оскільки правила нижче базових, вони перекривають попередні значення для того самого селектора. `opacity` створює плавну появу, `visibility` прибирає приховане меню з навігації клавіатурою. Клас `.is-open` встановлює JS після натискання кнопки. В HTML `aria-controls="primary-nav"` зв'язує кнопку з меню, `aria-expanded` повідомляє його стан.

**Формальне відхилення:** вправа вчить реалізувати бургер *тільки CSS*, через checkbox і `:checked`, із 0 рядків JS. Тут використано кнопку й JS. Це свідомий практичний вибір: кнопка має належну роль, а Escape працює. Сам модуль визнає ці переваги JS. Якщо викладач вимагає саме техніку checkbox, поточне рішення не зараховує цей конкретний пункт, хоча користувацька поведінка повніша. **Перевірено в браузері:** контрольні ширини 320, 375, 768, 769, 1024, 1025, 1440, 1920 px без переповнення сторінки; на 375 px меню відкривається й закривається, Escape повертає фокус, клік по посиланню закриває меню. **Не перевірено:** справжній телефон і безперервне перетягування ширини між контрольними точками.

## Модуль 4 — [фонові зображення й відео](https://9.lviv.ua/academy/web-development/images-video/)

**Висновок: основні вимоги реалізовано; потрібна перевірка на фізичному телефоні.** Hero — повноцінна секція з фоновим фото з вашої Figma, `cover`, позицією кадру та затемненням; фото має 1024 × 683 px і близько 263 КБ. Його завантаження пріоритетне через `preload`. Фон декоративний: увесь зміст є текстом HTML, тому окремий `alt` для CSS-фону не потрібен. На відміну від тега `<img>`, CSS-фон не резервує місце атрибутами `width/height`; місце задають `min-height` і padding секції.

```html
<link rel="preload" href="img/gym-floor.jpg" as="image">
<section class="hero">
  <div class="hero__pattern" aria-hidden="true"></div>
  <div class="container hero__inner">…</div>
</section>
```

```css
.hero {
  position: relative;
  background: var(--color-ink) url('../img/gym-floor.jpg') center 46% / cover no-repeat;
  min-height: 690px;
  padding: var(--sp-5) 0 var(--sp-4);
}
.hero__pattern {
  position: absolute;
  inset: 0;
  background: linear-gradient(90deg, rgba(10,10,9,.78), rgba(10,10,9,.23) 55%, rgba(10,10,9,.55));
  pointer-events: none;
}
.hero__inner { position: relative; }
```

`position: relative` робить hero системою координат для затемнення; `position: absolute` і `inset: 0` натягують шар на всю секцію. `cover` заповнює площу фото без деформації, але обрізає краї. `center 46%` зміщує точку фокуса; у мобільних медіа-запитах вона інша. Градієнт темніший там, де стоїть білий текст. `pointer-events: none` не дає невидимому шару перекрити кнопку. `min-height` задає нижню межу, але дозволяє секції вирости, якщо текст не вміщується; це безпечніше за фіксований `height`.

**Оновлення після надання MP4:** додано окрему секцію Training між Programs і Schedule. Вона має ваше відео (640 × 360, 27 секунд, приблизно 1,6 МБ), постер із його кадру, затемнення, текст та CTA. Основні вимоги модуля до фонового відео тепер реалізовані; перевірка на фізичному телефоні й повільному мобільному з'єднанні ще потрібна. Невеликий вихідний розмір відео може давати м'яке зображення на великих екранах.

```html
<video class="training__video" autoplay muted loop playsinline preload="none"
  poster="img/training-poster.jpg" aria-hidden="true" tabindex="-1">
  <source data-src="video/training.mp4" type="video/mp4">
</video>
```

`autoplay` просить автоматичний запуск, `muted` прибирає звук і дозволяє autoplay у більшості браузерів, `loop` повторює ролик, а `playsinline` залишає відео всередині сторінки на телефоні. `poster` показує нерухомий кадр до завантаження. `aria-hidden` і `tabindex=-1` виключають декоративний фон із читання та порядку Tab; керування доступне через окрему кнопку Play/Pause video.

Адреса спочатку лежить у `data-src`, тому MP4 не завантажується одразу. `IntersectionObserver` у `main.js` помічає наближення секції, присвоює `source.src`, викликає `video.load()` і `video.play()`. При виході секції за межі екрана або переході на іншу вкладку відео зупиняється. Змінна `userPaused` запам'ятовує паузу, яку користувач увімкнув сам, і не дозволяє автоматично її скасувати.

```css
.training__video { position: absolute; inset: 0; width: 100%; height: 100%; object-fit: cover; }
@media (prefers-reduced-motion: reduce) {
  .training__video, .training__toggle { display: none; }
}
```

`object-fit:cover` заповнює секцію без спотворення пропорцій і обрізає зайві краї. Псевдоелемент `.training::after` затемнює фон; текст і кнопки підняті над ним через `z-index`. За reduced-motion CSS приховує відео, а JS не підставляє адресу MP4 і не запускає його: залишається постер у CSS-фоні. Якщо браузер заборонив autoplay, кнопка Play video дозволяє запустити ролик вручну; помилка завантаження лишає читабельний текст і нерухомий фон.

## Модуль 5 — [форми й таблиці](https://9.lviv.ua/academy/web-development/forms-tables/)

**Висновок: частково.** Семантична форма й адаптивна таблиця є. `fieldset/legend` групують поля; у кожного поля є `label`, унікальний `id` і `name`. Використано текст, email, телефон, select і textarea — щонайменше чотири різні способи введення. `required`, `minlength` і `type="email"` запускають вбудовану перевірку браузера; `novalidate` відсутній. Клавіатурний фокус помітний, а `:user-invalid` додає рамку після помилки в браузерах, які його підтримують.

```html
<form class="form" action="#contact" method="post">
  <fieldset class="form__group">
    <legend class="visually-hidden">Your contact details</legend>
    <label class="form__label" for="name">Name</label>
    <input class="form__field" type="text" id="name" name="name"
           autocomplete="name" required minlength="2">
    <label class="form__label" for="email">Email</label>
    <input class="form__field" type="email" id="email" name="email"
           autocomplete="email" required>
    …
  </fieldset>
  <button type="submit">Request my trial class</button>
</form>
```

`for="name"` і `id="name"` пов'язують підпис із полем: клік по підпису ставить курсор у поле, а програма зчитування екрана знає його назву. `name` — ключ, під яким значення пішло б на сервер; `id` — локальний ідентифікатор для HTML/CSS/JS. `autocomplete` дозволяє браузеру підставити дані користувача. `required` блокує порожнє значення; email перевіряє формат. `method="post"` доречний для заявки, бо дані не повинні потрапляти в URL. `action="#contact"` поки лише заглушка.

```html
<div class="table-wrap">
  <table class="schedule-table">
    <caption>Class schedule, Monday to Saturday</caption>
    <thead><tr><th scope="col">Time</th>…</tr></thead>
    <tbody><tr><th scope="row">06:30</th><td>Strength</td>…</tr></tbody>
  </table>
</div>
```

`caption` називає всю таблицю, `thead` містить заголовки колонок, `tbody` — дані, `scope="row"/"col"` пояснює, з якими значеннями пов'язаний заголовок. CSS `overflow-x: auto` стоїть на `.table-wrap`, а `min-width: 640px` — на таблиці: на телефоні прокручується лише таблиця, не вся сторінка.

JS робить демо-форму чесною: після валідного заповнення `event.preventDefault()` не дає браузеру надіслати дані на неіснуючу адресу, а `role="status"` повідомляє, що заявка **не** відправлена. Це не виконує кінцеву вимогу уроку: в `action` немає сервісу-приймача, тестовий лист не приходив. Для справжньої форми потрібні обраний вами сервіс/бекенд і перевірка доставки. Сам HTML/CSS-чек-лист форми виконується, функціональний фінал модуля — ні.

## Модуль 6 — [UI-компоненти й тарифи](https://9.lviv.ua/academy/web-development/ui-components/)

**Висновок: переважно так.** Кольори, радіуси, основні відступи й тінь зібрані у `:root`. Кнопка має базу `.btn` і варіанти `.btn--primary`, `.btn--accent`, `.btn--ghost`. Чотири програми, чотири тренери, три відгуки та три тарифи використовують повторювані класи. Три плани мають назву, ціну, список і дію. Середній `.plan--featured` виділений і залишається другим на телефоні, як ви попросили за макетом. Це відрізняється від пункту уроку про featured першим. Цей прохід додав зміну фону тарифу при наведенні, якої раніше не було.

```css
.btn { min-height: 48px; border-radius: var(--r-pill); transition: background .2s ease, transform .15s ease; }
.btn--primary { background: var(--color-red); color: var(--color-paper); }
.btn--ghost { border-color: currentColor; color: inherit; }
.plan { display: flex; flex-direction: column; transition: background-color .2s ease, transform .2s ease; }
.plan:hover { background: var(--color-paper-hover); transform: translateY(-4px); }
.plan__btn { margin-top: auto; }
@media (max-width: 768px) { .pricing__grid { flex-direction: column; } }
```

Базовий `.btn` визначає форму й розмір один раз; модифікатор змінює тільки вигляд. `min-height: 48px` дає зручну ціль для пальця. `display:flex; flex-direction:column` усередині тарифу ставить вміст вертикально, а `margin-top:auto` виштовхує кнопку донизу — кнопки вирівнюються, навіть якщо списки різної довжини. На телефоні `flex-direction:column` ставить тарифи вертикально. Правило `order:-1` видалено, тому візуальний і HTML-порядок однакові: $18 → $129 → $99. Hover є тільки підсиленням: ціна й переваги видно без наведення.

**Два обмеження чек-листа:** буквальна вимога «усі відступи кратні 8» не виконана для деяких дрібних значень (`14px` у кнопці/таблиці, `6px` у label тощо); їх потрібно звіряти з Figma, а не механічно округляти. Повний обхід усієї сторінки клавішею Tab на реальному телефоні ще не задокументований.

## Модуль 7 — [CSS-анімації](https://9.lviv.ua/academy/web-development/css-animation/)

**Висновок: так за трьома прийомами, перевірка на телефоні лишається.** Урок рахує три різні типи руху: (1) `transition` для зміни станів, (2) `transform` для зсуву, (3) власну появу через `@keyframes`. У коді присутні всі три. Попередній аудит помилково тлумачив це як потребу трьох різних `@keyframes`; такої вимоги на сторінці модуля немає.

```css
.program-card { transition: transform .2s ease, border-color .2s ease; }
.program-card:hover { transform: translateY(-4px); }
@keyframes hero-enter {
  from { opacity: 0; transform: translateY(12px); }
  to   { opacity: 1; transform: translateY(0); }
}
@media (prefers-reduced-motion: no-preference) {
  .hero__copy { animation: hero-enter .5s ease-out both; }
  .hero__content { animation: hero-enter .5s .16s ease-out both; }
}
```

`transition` ставлять у звичайний стан, щоб і наведення, і повернення були плавними. У ньому перелічені конкретні властивості, не `all`. `transform` рухає картку візуально, не змінюючи місця сусідів. `@keyframes` описує початковий і кінцевий кадри; `both` утримує початковий стан до старту та кінцевий після завершення. Затримка `.16s` робить появу тексту пізнішою за заголовок. Анімація запускається лише за `no-preference`, а загальне правило `prefers-reduced-motion: reduce` майже вимикає решту руху. Короткі hover-переходи не блимають нескінченно. Тривалість входу скорочено до `.5s` за орієнтиром уроку.

### Розбір HTML від початку до кінця

У `<head>` є також `meta name="theme-color"` для кольору системної панелі у підтримуваних браузерах, `preload` локального Anton і `css/fonts.css` для локальних шрифтів та `rel="icon"` для вкладки. Посилання на локальні файли відносні до місця `index.html`: `css/style.css` шукається всередині `css/`, а в самому CSS `../img/gym-floor.jpg` піднімається на один каталог вище від `css/`. Амперсанд у тексті записаний як `&amp;`, щоб HTML не сприйняв його як початок сутності.

У header логотип — справжнє посилання на `#top`; логотип тепер використовує наданий PNG гантелі: темний у шапці, світлий у футері. CSS-обгортка обрізає порожні краї зображення без зміни самого файлу. `aria-hidden="true"` прибирає декоративний малюнок із читання, а `aria-label` на посиланні дає зрозумілу назву. Пункти меню зібрані в `<ul>`, бо це перелік навігаційних опцій. `aria-label="Primary"` відрізняє його від навігації у footer. Skip-посилання видалено за вашим запитом; `main` залишається семантичним орієнтиром.

Hero містить тільки один `h1` на сторінці. `<br>` фіксує перенос у заголовку з макета; за потреби при зміні тексту його слід переглянути. Два CTA — це `<a>`, а не `<button>`, тому що вони переводять до іншої секції (`#contact`, `#schedule`), а не виконують дію у поточному стані. Статистика — `<dl>`: кожен `dt` називає показник, `dd` дає його число. Обгортки `<div>` тут потрібні для розкладки трьох пар поряд; семантика лишається у `dt/dd`.

У секціях Programs і Coaches кожна картка — `<article>`, а заголовок картки — `h3` під заголовком секції `h2`. Букви S/C/M/O та ініціали тренерів мають `aria-hidden="true"`, бо назви програм і повні імена вже є поруч як текст: подвійне озвучення заважало б. У Reviews тег `<blockquote>` позначає саме цитату, `<figcaption>` підписує її автором. У Pricing `<ul>` містить опції тарифу; ціни написані текстом, а не вставлені картинкою, тож їх можна знайти, скопіювати й прочитати програмою зчитування екрана.

У контактах `<dl>` так само пов'язує «Address/Hours/Phone» зі значеннями. Телефон виглядає як приклад, тому не зроблений фальшивим `tel:`-посиланням. У формі `legend` прихований лише візуально класом `.visually-hidden`: він лишається доступним технологіям читання. Кожен `label` стоїть перед власним полем, а `select` і `textarea` доповнюють звичайні `input`. `form__note` видимий до заповнення, тому людина завчасно знає, що це прототип. `form__status` спочатку має `hidden`, а JS відкриває його після спроби валідного надсилання.

Footer повторює найважливіші якорі для людини, яка дійшла до низу сторінки. Соціальні знаки поки `<span role="img">`, тому їх не можна натиснути; це чесніше за `href="#"`, який удавав би справжній профіль. Коли з'являться реальні URL, замініть ці span на `<a href="…">` із зрозумілими `aria-label`.

### Розбір CSS за порядком файлу

1. **Reset.** `box-sizing: border-box` спрощує розрахунок ширин. `margin:0` прибирає різні стандартні відступи браузерів; `img, svg { max-width:100%; display:block; }` не дає зображенням вилазити й усуває маленький проміжок під рядковим SVG. Скидання `list-style` прибирає стандартні маркери списків; у тарифах власний маркер малюється через `li::before`.
2. **Токени.** У `:root` лежать змінні, які успадковує сторінка. `var(--sp-3)` підставляє значення `24px`. Кольори `ink/paper/red` задають ієрархію, `muted-light/muted-dark` розділяють приглушений текст за тлом. `--container-w` обмежує ширину, `--shadow-lift` використовується лише на головному тарифі. У медіа-запиті `:root { --container-pad: 16px; }` змінює один токен для всіх контейнерів на телефоні.
3. **Типографіка та фокус.** `h1/h2/h3` мають різні масштаби й коротшу `line-height`, бо display-шрифт високий. Звичайний текст має вищу міжрядкову відстань для читання. `:focus-visible` малює контур для клавіатури; правило `.form__field:focus-visible` повторює його після локального стилю `.form__field:focus`, який прибирає системний outline і ставить тінь. Без останнього правила клавіатурний контур форми міг би зникнути через каскад CSS.
4. **Layout.** `.container` обмежує й центрує вміст; програми/тренери/відгуки використовують Flexbox із `flex-wrap`. `.pricing__grid` теж Flexbox, щоб три плани були в одному ряду з однаковою висотою. `.section-head` задає однаковий максимальний рядок і відступ після заголовка секції.
5. **Компоненти.** `.btn` — загальна форма кнопок; модифікатори змінюють колір. `.logo` збирає PNG-гантелю і напис у ряд. `.program-card`, `.coach-card`, `.review-card` ділять фон, рамку, радіус і анімацію; нижче правила для кожного типу задають його деталі. `.plan` — вертикальний Flexbox, `.plan--featured` перевизначає темний фон і червону рамку, `.plan__badge` абсолютно розташований біля верхнього краю. Таблиця має власні правила, бо таблична розкладка відрізняється від карток. Поля форми мають спільний клас, щоб текст, email, телефон, select і textarea виглядали однаково.
6. **Секції.** `.header { position:sticky; top:0; z-index:50; }` лишає навігацію вгорі під час прокрутки. `z-index` дає меню опинитись над рештою сайту. Hero має фото й градієнт; `.hero__inner` ставить заголовок угорі, а опис із кнопками ближче донизу через `justify-content:space-between`. `margin-left:auto` зсуває цей нижній блок праворуч на desktop. Programs/Pricing — світлі; Schedule/Contact/Footer — темні; Coaches/Reviews мають м'який світлий фон. `scroll-margin-top` на секціях лишає місце під липкою шапкою, коли користувач переходить за якорем.
7. **Медіа-запити.** До 1024 px картки стають по дві; до 768 px з'являється бургер, меню отримує абсолютну панель, картки й контакт стають вертикальними; до 480 px шрифти, відступи й кнопки пристосовуються до 320–375 px. Правила стоять наприкінці, тому їм легше перевизначати desktop-значення. `prefers-reduced-motion` скорочує рух для людей, які вимкнули анімації у системі.

**Як працює каскад на практиці:** загальне `.btn` задає мінімальну висоту, `.btn--primary` — червоний фон, а `.hero .btn--ghost` — світлий текст лише в темному hero. Одному елементу можуть відповідати кілька правил. Браузер обирає за походженням, важливістю, специфічністю та порядком у файлі; тому responsive-правила стоять нижче. Замість додавання `!important` при кожній проблемі перевіряйте в DevTools, яке правило перекрило інше.

### Як працює весь `main.js` крок за кроком

1. `(function () { … })();` одразу викликає функцію й не засмічує глобальну область змінними `toggle`, `nav`, `form`.
2. `querySelector`/`getElementById` знаходять елементи. `if (!toggle || !nav) return` не дає скрипту впасти, якщо елемент видалять із HTML.
3. `openNav` додає `.is-open` і ставить `aria-expanded="true"`; `closeNav` робить зворотне. `isOpen` читає той самий CSS-клас, тобто має одне джерело стану.
4. Обробник `click` на кнопці перемикає меню. Обробники на посиланнях закривають його після вибору розділу.
5. Обробник `keydown` перевіряє Escape та повертає фокус на кнопку; клік поза header закриває меню; `resize` прибирає мобільний стан після переходу на desktop.
6. Другий IIFE шукає форму й живий статус. Браузер спершу виконує HTML-валідацію; подія `submit` виникає лише для валідних полів. `preventDefault()` зупиняє мережевий запит, `hidden=false` відкриває текст, `role="status"` дає озвучення, `focus()` переміщує клавіатурний фокус до пояснення.

### Як перевіряти себе після кожної правки

1. Почніть зі структури HTML: тег показує **що це**, клас указує CSS/JS **як воно виглядає або поводиться**.
2. У DevTools виберіть елемент і знайдіть його правило. Перекреслений CSS означає, що інше правило виграло за каскадом/специфічністю або прийшло пізніше.
3. Звузьте сторінку через 1024, 768, 480 до 320 px. Перевірте `document.documentElement.scrollWidth <= window.innerWidth`, фото, кнопки й таблицю.
4. Пройдіть сторінку лише клавішею Tab, потім відкрийте мобільне меню Space і закрийте Escape. Перевірте форму: порожнє ім'я, неправильний email, валідні тестові значення.
5. В Network переконайтесь, що фото/стилі/JS завантажились і немає зайвого великого ресурсу. Перед публікацією повторіть це на справжньому смартфоні.

**Що принципово не завершено:** реальні дані залу, сервіс-приймач заявки, вимірювання Figma Inspect, справжній мобільний тест, GitHub remote/Pages. Ці пункти не можна довести одним лише наявним кодом.


У горизонтальному Flexbox `flex-basis:420px` задавав початкову ширину. Після `flex-direction:column` основна вісь стала вертикальною, і те саме значення почало задавати висоту. Тому під контактними деталями з'являлося велике порожнє місце. `flex:0 1 auto` повертає висоту за вмістом. `width:100%` розтягує форму на ширину контейнера, а `max-width:none` скасовує desktop-обмеження 480 px. `min-inline-size:0` на fieldset дозволяє йому стискатися навіть із довгими підписами.

У футері перший `flex-direction:column` ставить логотип, навігацію та соціальні іконки один під одним. Окремий такий самий напрям на `.footer__nav ul` ставить кожен пункт навігації в новий рядок. `align-items:center` центрує елементи поперек вертикальної осі. Соціальні іконки зберігають власний горизонтальний Flexbox.

У меню `.nav__list { text-align:center }` центрує текст, а `.nav__cta { width:220px; min-height:56px; align-self:center }` задає потрібні розміри й положення кнопки. `max-width:100%` не дозволяє їй вийти за межі вузької панелі.

`css/fonts.css` оголошує локальні Anton і Inter через `@font-face`. `font-display:swap` дозволяє одразу показати текст запасним шрифтом і замінити його після завантаження WOFF2. Для Inter `font-weight:400 800` описує діапазон ваг в одному variable-файлі. Ліцензії лежать поруч у `fonts/`.
