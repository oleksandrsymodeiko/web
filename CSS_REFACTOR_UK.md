## Використання кольорів до змін

Це кількість посилань `var(...)` у CSS без оголошення змінної. Вона показує використання в коді, а не площу кольору на екрані: один фон секції може займати більше місця, ніж десять маленьких написів.

| Змінна | Посилань | Рішення |
|---|---:|---|
| `--color-paper` | 26 | Залишено: світлий фон і текст. |
| `--color-red` | 14 | Назву залишено; єдине значення тепер #AE1F1F. |
| `--color-ink` | 13 | Залишено: основний темний колір. |
| `--color-mist` | 7 | Об’єднано з приглушеним текстом на темному тлі: rgba світлого кольору з .78. |
| `--color-muted-light` | 6 | Перейменовано на --color-muted; той самий #625F55. |
| `--color-paper-soft` | 5 | Залишено: тло карток та чергування секцій. |
| `--color-line` | 5 | Прибрано з :root; рамки використовують rgba основного темного кольору. |
| `--color-line-dark` | 4 | Прибрано з :root; рамки використовують rgba основного світлого кольору. |

| `--color-paper-hover` | 1 | Замінено на наявний --color-paper для hover тарифу. |
| `--color-red-dark` | 1 | Окрему змінну видалено; її значення стало єдиним червоним. |

| `--color-olive` | 0 | Видалено: жодного застосування. |

## П’ять базових кольорів після змін

```css
:root {
  --color-ink: #14140F;
  --color-paper: #F1EEE6;
  --color-paper-soft: #E7E2D6;
  --color-red: #AE1F1F;
  --color-muted: #625F55;
}
```

Єдиним червоним обрано колишній темніший #AE1F1F: контраст напису #F1EEE6 на ньому приблизно 6,01:1; на #D62828 був 4,32:1. Тому це покращує читабельність звичайного дрібного тексту кнопок. Hover червоної кнопки тепер позначається легким підняттям і тінню. У світлого тарифу фон при hover змінюється на вже наявний paper.

У CSS також є `rgba(...)`: це п’ять базових кольорів із прозорістю для рамок, тіней, накладок і приглушеного тексту. Результат накладання дає похідні відтінки. Це не твердження, що весь сайт, включно з фотографіями й PNG, містить буквально лише п’ять видимих кольорів. Наприклад, `rgba(241,238,230,.08)` — світлий базовий колір із непрозорістю 8% поверх темної секції. Поля залишаються відмінними від фону.

На темних секціях клавіатурний фокус тепер світлий. Малий напис над заголовком hero також світлий, щоб читатися поверх фото.

## Медіазапити

Було шість блоків `@media`: три для ширини, два для reduced-motion і один для no-preference. Стало два:

```css
@media (max-width: 900px) { /* мобільна розкладка */ }
@media (prefers-reduced-motion: reduce) { /* зменшення руху */ }
```

До 900 px включно показується бургер, картки й Contact стають вертикальними, футер центрується. Вище 900 px працює desktop-розкладка. JS скидає відкритий стан меню вище того самого порога, тому CSS і JS узгоджені. 900 px — поріг, обраний за місцем, потрібним навігації та карткам; це не окремий дизайн планшета.

Проміжні ширини все одно потрібно перевіряти: браузер не знає, який пристрій називається планшетом. Шрифти, відступи контейнера та секцій плавно змінюються через `clamp()`, тому для кожного їхнього розміру не потрібен окремий медіазапит.

```css
h2 { font-size: clamp(26px, 3.34vw, 48px); }
```

Мінімальний шрифт — 26 px, бажаний — 3,34% ширини вікна, максимальний — 48 px. На вузькому екрані працює мінімум, на широкому — максимум; між ними розмір плавний. Основні desktop/mobile композиції залишаються окремими.

## Що в коді було зайво ускладнене

За кодом неможливо надійно встановити, чи його написала людина або ШІ. BEM, CSS-змінні, Flexbox і семантичний HTML — звичайні прийоми. Оцінювати варто зрозумілість та відповідність задачі.

Прибрано невикористані concrete, olive та відступ sp-8, зведено повторні медіазапити, об’єднано два оголошення контейнера й повторне правило hero__text. Скорочено довгі коментарі про «industrial palette», порівняння з іншими палітрами та історію попередніх помилок: у робочому CSS вони не допомагають розуміти поточне правило. Також вилучено коментар про off-canvas: меню фактично розкривається під шапкою.

Збережено змістовні назви класів, короткі коментарі секцій, семантичні теги та обробники Escape/відеопаузи. Три невеликі функціональні блоки JS мають різні задачі; об’єднання їх в одну велику функцію не робить код зрозумілішим. Варто вміти пояснити `calc`, `clamp`, flex-basis, каскад і IntersectionObserver; відповідні пояснення є в навчальному посібнику. Вигадані відгуки та дані тренерів слід замінити справжніми, якщо сайт готується для реального закладу.
