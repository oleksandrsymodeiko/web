## 2. Короткий словник синтаксису перед розбором

### Змінна, властивість, метод і функція

```js
var nav = document.getElementById('primary-nav');
```

- `var` — оголошення змінної.
- `nav` — ім'я, яке обрав автор коду. Воно могло б називатися `menu`, якби всі подальші звернення також змінилися.
- `=` — присвоїти значення змінній. Це не перевірка рівності.
- `document` — об'єкт поточного HTML-документа, який надає браузер.
- `getElementById` — метод: функція, доступна через об'єкт.
- `('primary-nav')` — виклик методу з аргументом: шуканим `id`.
- `'primary-nav'` — рядок тексту. Лапки позначають рядок; вони не стають частиною самого `id`.
- `;` — кінець інструкції. Часто JavaScript може вставити його автоматично, але тут завершення записані явно.

`var` має область видимості функції. У новому коді можна було б використати `const` для посилань на DOM-елементи й `let` для станів, які переприсвоюються. Поточний `var` працює; його заміна сама по собі не скоротить логіку. `const` забороняє переприсвоювати змінну, але не забороняє змінювати властивості об'єкта, на який вона посилається.

```js
video.paused
video.pause()
```

`paused` — властивість, яку читаємо, щоб дізнатися стан. `pause()` — метод, який викликаємо, щоб виконати дію. Дужки `()` тут принципові.

### Основні оператори

| Запис | Значення |
|---|---|
| `=` | Присвоїти значення. |
| `===` | Перевірити строгу рівність, без автоматичного перетворення типів. |
| `!value` | Логічне НЕ: перетворити значення на булеве й інвертувати. |
| `a || b` | Логічне АБО; у цих умовах достатньо однієї істинної частини. |
| `a && b` | Логічне І; у цих умовах потрібні всі істинні частини. |
| `condition ? a() : b()` | Якщо умова істинна — виконати `a()`, інакше — `b()`. |
| `object.property` | Звернутися до властивості об'єкта за її назвою. |
| `array[0]` | Взяти перший елемент: індекси починаються з нуля. |
| `{ ... }` | Залежно від місця: тіло функції/умови або об'єкт із параметрами. |

`||` і `&&` обчислюються зліва направо й можуть зупинитися раніше. Наприклад, `header && header.contains(...)` не викличе `.contains()`, якщо `header` не знайдений. У загальному JavaScript ці оператори можуть повертати самі значення операндів; тут вони використані всередині умов.

`true` та `false` — булеві значення. `'true'` та `'false'` у лапках — текст. Непорожній рядок `'false'` у звичайній JS-умові все одно вважається істинним. Але для HTML-атрибута `aria-expanded` потрібні саме текстові значення `'true'` / `'false'`.

### Функція, виклик і обробник події

```js
function closeNav() { /* інструкції */ }
closeNav();
link.addEventListener('click', closeNav);
```

Перший запис оголошує функцію. Другий виконує її зараз. Третій передає функцію браузеру: виконати її пізніше, коли станеться клік. Якби в третьому записі написали `closeNav()`, функція виконалася б відразу під час підключення обробника.

`function () { ... }` — функція без власного імені. Коли її передають в `addEventListener`, браузер зберігає її та викликає у відповідь на подію. Така функція називається callback, або функція зворотного виклику.

### DOM: що змінює JS

Браузер перетворює HTML на дерево об'єктів — DOM. `querySelector()` повертає посилання на об'єкт елемента, а не копію тексту його HTML. Тому `nav.classList.add(...)` змінює клас справжнього меню на сторінці.

Назви CSS-класів `is-open` і `is-ready` — звичайні домовленості цього проєкту. Браузер не знає сам, що вони означають: їхній вигляд описаний у CSS.

### Рядок 6. Окрема функція, яку одразу викликають

```js
(function () {
```

Це початок конструкції IIFE — Immediately Invoked Function Expression. У кінці частини, в рядку 55, є її завершення `})();`.

`function () { ... }` створює функцію без назви. Зовнішні дужки роблять її виразом, а фінальні `()` викликають одразу. Усе всередині виконується один раз під час завантаження скрипту, щоб знайти елементи й зареєструвати події. Самі обробники кліків потім виконуватимуться багато разів.

Це створює окрему область видимості: локальний `toggle` меню не конфліктує з `toggle` відео в іншій IIFE. Для такого сайту це один зі способів організації, а не обов'язкова вимога. Три IIFE не означають три потоки чи паралельне виконання.


### Рядок 7. Знайти кнопку меню

```js
  var toggle = document.querySelector('.nav-toggle');
```

`document.querySelector()` шукає перший елемент, який відповідає CSS-селектору. Крапка в `'.nav-toggle'` означає клас. Це та сама логіка селектора, що в CSS.

Результат зберігається в `toggle`:

```html
<button class="nav-toggle" type="button" aria-expanded="false" aria-controls="primary-nav">
```

Якщо елемент не знайдений, результат — `null`. У файлі одна така кнопка. Якби їх було декілька, `querySelector()` усе одно повернув би лише першу.


### Рядок 8. Знайти кероване меню

```js
  var nav = document.getElementById('primary-nav');
```

`getElementById('primary-nav')` знаходить елемент із відповідним `id`. Символ `#` тут не пишуть: метод уже шукає саме за ідентифікатором. Через CSS-селектор аналогічний пошук виглядав би як `document.querySelector('#primary-nav')`.

У HTML це `<nav class="nav" id="primary-nav" ...>`. Значення збігається з `aria-controls` на кнопці. `id` має бути унікальним. Якщо елемента немає, отримуємо `null`.


### Рядки 9–10. Не продовжувати, якщо потрібних елементів немає

```js
  if (!toggle || !nav) return;
```

Рядок 9 порожній — відділяє пошук від перевірки.

`!toggle` означає «кнопку не знайдено», `!nav` — «меню не знайдено». Через `||` достатньо відсутності хоча б одного елемента. `return` одразу завершує поточну IIFE без значення.

Це не завершує весь файл: наступні дві IIFE все ще можуть запуститися. Перевірка запобігає спробам викликати метод у `null`. Вона корисна для повторного використання скрипту, але не повідомляє користувачеві про помилку розмітки — частина просто не підключиться.

Порожній рядок 11 відділяє функції від перевірки. `function openNav()` оголошує іменовану функцію без параметрів. `openNav` — авторська назва «відкрити навігацію», а не вбудована команда браузера.

Відкривальна `{` починає її тіло. На цьому рядку меню ще не відкривається: інструкції виконаються, коли хтось викличе `openNav()`. Функція використовує змінні `nav` і `toggle` зі своєї зовнішньої області видимості.


### Рядок 13. Додати CSS-клас відкритого стану

```js
    nav.classList.add('is-open');
```

`classList` — властивість DOM-елемента, яка надає доступ до його класів. `add('is-open')` додає один клас, зберігаючи вже наявний `nav`. Повторне додавання того самого класу не створить дубліката.

Було `<nav class="nav">`, стало `<nav class="nav is-open">`. CSS `.nav.is-open` показує мобільну панель: змінює прозорість, видимість і зміщення. JS тут не записує розміри чи кольори — він лише перемикає стан, який оформлює CSS.


### Рядок 14. Повідомити про відкритий стан кнопки

```js
    toggle.setAttribute('aria-expanded', 'true');
```

`setAttribute(назва, значення)` задає HTML-атрибут. Перший аргумент — `'aria-expanded'`, другий — текст `'true'`, бо меню тепер розгорнуте.

Це повідомляє стан допоміжним технологіям. У CSS проєкту цей атрибут також використовується для перетворення ліній бургера на хрестик. Сам атрибут не відкриває панель — для цього вище додано `is-open`.

Обидва записи потрібні для узгодження: панель відкрита, кнопка повідомляє «розгорнуто» й має відповідний вигляд. Прибрати лише один із них — означає розсинхронізувати ці частини.


Після порожнього рядка 21 оголошується `isOpen()`. Її назва означає питання «відкрито?».

### Рядки 25–28. Перемикати меню після натискання кнопки

```js
  toggle.addEventListener('click', function () {
```

Це той самий зміст у довшому записі. `isOpen()` спершу викликається й повертає стан. Якщо меню відкрите — закриваємо, інакше — відкриваємо.

У рядку 28 `}` закриває callback, `)` завершує `addEventListener`, а `;` — інструкцію. Ця конструкція `});` повториться в інших обробниках із тим самим призначенням.


### Рядки 29–33. Закривати після вибору навігаційного посилання

```js
  // Close after choosing a link — the menu shouldn't stay open on navigation.
  nav.querySelectorAll('a').forEach(function (link) {
    link.addEventListener('click', closeNav);
  });
```

Рядок 29 порожній, 30 — коментар із наміром. Рядок 31 шукає всі теги `a` всередині вже знайденого `nav`. Це обмежений пошук: посилання футера чи інших секцій сюди не потраплять. Результат `querySelectorAll()` — статичний `NodeList` знайдених елементів, не звичайний масив, хоча тут він підтримує `.forEach()`.

`forEach(function (link) { ... })` проходить кожне посилання. `link` — параметр callback: поточний елемент. Назву можна було б змінити, але тоді й звернення в рядку 32 треба змінити.

Рядок 32 передає `closeNav` як готовий обробник кліку. Дужок після `closeNav` немає, бо закривати треба в момент майбутнього кліку, а не під час реєстрації. Рядок 33 закінчує перебір.

`preventDefault()` тут немає, тому звичайний перехід за `href="#contact"` зберігається: меню закривається, а браузер переходить до секції. Логотип поза `nav` не входить у цей список.

### Рядки 42–49. Закривати після кліку за межами шапки

### Рядки 83–85. Спробувати відтворення й обробити відмову

```js
    // Autoplay may be blocked by browser settings; the Play button remains.
    var playback = video.play();
    if (playback) playback.catch(function () {});
```

Рядок 83 пояснює, що autoplay може блокуватися налаштуваннями браузера. Рядок 84 викликає `video.play()` і зберігає результат у `playback`.

У сучасних браузерах `play()` повертає `Promise` — об'єкт майбутнього результату. Запуск медіа асинхронний: даних може ще не вистачати, запуск може бути дозволений або відхилений. Promise завершиться успішно, коли відтворення розпочнеться, або перейде у відхилений стан, наприклад через заборону autoplay. Змінна `playback` — це не `video.paused` і не саме відео.

У рядку 85 `if (playback)` перевіряє наявність результату перед `.catch()`. Це запас на старі реалізації, де `play()` міг не повертати Promise; у сучасному браузері результат є об'єктом Promise.

`.catch(function () {})` підключає обробник відхилення. Усередині порожньо: помилка приймається, але не показується й не обробляється докладніше. Це запобігає необробленому відхиленню Promise; **не** змушує відео відтворюватися й **не** розв'язує саму причину відмови. Кнопка Play лишається доступною.

Відхилення можливе й через переривання очікуваного запуску методом `pause()`, а не тільки через заборону autoplay. Порожній catch тут спрощує ці очікувані переходи, але ускладнює діагностику несподіваних помилок. Це один із конкретних моментів для майбутнього обговорення, а не вимога терміново все переписати.

Без `userPaused` observer міг би знову запустити відео після повернення до секції, хоча користувач перед цим натиснув Pause. Ця змінна зберігає його вибір у межах поточного завантаження сторінки.

### Рядок 106. Перевірити наявність IntersectionObserver

```js
  if ('IntersectionObserver' in window) {
```

Оператор `in` перевіряє, чи є властивість із назвою `'IntersectionObserver'` в об'єкті `window`. Якщо API доступний, виконується основна гілка з відстеженням секції. Якщо ні — код переходить до `else`.

Це перевірка можливості браузера, а не перевірка назви чи версії Chrome/Firefox. Для сучасних браузерів API зазвичай доступний; запасна гілка потрібна для середовища без нього.


### Рядок 107. Створити спостерігач за положенням секції

```js
    var observer = new IntersectionObserver(function (entries) {
```

`new IntersectionObserver(...)` створює об'єкт спостерігача. `new` використовується з конструктором API. Змінна `observer` зберігає створений об'єкт, щоб далі викликати `.observe(section)`.

Перший аргумент — callback `function (entries) { ... }`. Браузер передасть у `entries` масив записів про перетини. Це не самі теги section: кожен запис містить дані спостереження, зокрема `isIntersecting`.

Callback запускається асинхронно після початку спостереження й змін перетину, а не безперервно на кожен кадр відео. Тому немає потреби вручну перевіряти координати на кожен scroll.


### Рядок 108. Взяти стан перетину першого запису

```js
      nearby = entries[0].isIntersecting;
```

`entries[0]` означає перший запис масиву. Нумерація починається з 0. Його властивість `.isIntersecting` повертає `true` або `false` для перетину з областю спостереження.

Це значення записується в `nearby`. У цьому коді observer стежить тільки за однією секцією, тому взято перший запис. Якби тим самим observer стежили за багатьма відеосекціями, логіку потрібно було б будувати окремо для кожної, а не сліпо брати `entries[0]`.

`nearby` тут не означає «увесь блок повністю видно» чи «користувач точно дивиться на нього». Це лише результат геометричної перевірки observer з налаштуванням нижче.


### Рядки 109–110. Перерахувати відтворення і задати запас 100px

```js

    }, { rootMargin: '100px' });
```

Рядок 109 викликає `updatePlayback()` одразу після зміни `nearby`.

У рядку 110 `}` закінчує callback, а після коми передається другий аргумент конструктора — об'єкт налаштувань `{ rootMargin: '100px' }`.

`rootMargin` — відступ області спостереження. Одне значення `100px` застосовується до всіх чотирьох сторін. Оскільки `root` не заданий, основою є viewport; позитивний відступ збільшує його область на 100 CSS-пікселів з кожного боку.

Тому відео може почати завантажуватися й відтворюватися ще до фактичної появи на екрані. Так само воно може продовжувати відтворення, перебуваючи до 100px поза видимою областю. Коментар «pause offscreen» описує намір спрощено: фактично використано буферну зону. Це не таймер 100 мс і не 100% видимості.

100px — обраний невеликий запас, а не обов'язкове значення API. За 0px запасу не буде. Параметр `threshold` не заданий: використовується стандартний поріг 0. У цьому коді рішення береться через `isIntersecting`, а не через вимогу бачити певний відсоток секції.


### Рядок 111. Почати спостерігати саме за цією секцією

```js
    observer.observe(section);
```

`observer.observe(section)` підключає знайдений у рядку 60 DOM-елемент до спостерігача. Саме створення `new IntersectionObserver(...)` ще не визначало, за яким елементом стежити.

Після observe браузер надасть початкові дані перетину, тож nearby перестане бути лише початковим false. Подальші сигнали змінюватимуть його при прокрутці.

Спостерігається вся `.training`, а не лише `<video>`, тому результат прив'язаний до положення секції з текстом і фоном.

### Рядок 125. Слухати надсилання всієї форми

```js

```

`form.addEventListener('submit', ...)` реагує на спробу стандартного надсилання форми. Подія прив'язана до form, а не до натискання кнопки. Тому обробляється також надсилання клавішею Enter з відповідного поля.

Браузер передає об'єкт події у `event`. У звичайному процесі надсилання спочатку перевіряються HTML-обмеження: `required`, `type="email"`, `minlength="2"`. Якщо поле невалідне й перевірку не вимкнено, браузер не доходить до звичайної події submit цієї форми. У поточній розмітці `novalidate` немає.

Тому цей код не перевіряє ім'я чи email власними регулярними виразами: стандартну перевірку вже задає HTML. Вона не підтверджує реальність адреси та не замінює серверну перевірку, коли буде справжній приймач.


### Рядок 126. Зупинити стандартний мережевий запит форми


`event.preventDefault()` скасовує стандартну дію саме цієї події — надсилання форми браузером. Це не команда зупинити весь JavaScript і не припинення спливання події: для спливання існує інший метод, якого тут немає.

У HTML вказані `method="post"` та `action="#contact"`. Фрагмент #contact — не сервіс, який приймає заявки. Без цього перехоплення форма могла б спробувати POST на поточну адресу сторінки, що для статичного сайту не забезпечує обробку заявки.

Цей рядок сам нічого не надсилає замість стандартного запиту. У коді немає fetch, email-сервісу, бази даних або іншого отримувача.

Абзац уже існує в HTML; код не створює новий елемент через createElement. Він лише показує підготовлений елемент і наступним рядком записує текст.

## 6. Як виконання пов'язане в часі

### При першому відкритті сторінки

1. HTML створює кнопки, меню, video, source та форму.
2. Браузер доходить до підключення main.js унизу body.
3. Перша IIFE знаходить меню, оголошує функції й підключає його події. Вона сама не відкриває меню.
4. Друга IIFE знаходить відео, задає початкові стани, підключає події й спостереження за секцією. Якщо observer доступний, його callback надасть початковий стан окремо, асинхронно.
5. Третя IIFE підключає submit форми. Вона сама не показує повідомлення.
6. Коли виникають події, запускаються тільки призначені їм обробники.

### Натискання бургера

`click` → `isOpen()` → `openNav()` або `closeNav()` → клас панелі + aria-expanded кнопки → CSS показує чи приховує меню.

Після цього той самий клік може дійти до document. Перевірка header.contains не дає одразу закрити меню після його відкриття.

### Прокручування до відео

Observer → `nearby = true` → `updatePlayback()` → перевірка чотирьох умов → перше підключення src за потреби → `play()` → подія playing → показ відеошару й напис Pause video.

Під час наступного входу в зону джерело повторно не ініціалізується. Якщо userPaused залишився true, відео не запуститься, поки людина не дозволить його кнопкою.

### Натискання Submit

Перевірка браузера за HTML-атрибутами → подія submit, якщо форма валідна → preventDefault → показ статуса → текст про відсутність відправлення → focus на повідомленні.

## 7. Чи справді JavaScript забагато для цього сайту

Так, його можна суттєво скоротити, якщо змінити набір потрібної поведінки. Для простого навчального лендингу більшість дій навколо відео й частина обробників меню є додатковими. Водночас самі 131 рядок включають порожні рядки, коментарі, фігурні дужки та три різні задачі — це не 131 окрема складна можливість.

Нижче немає рішення «видалити все»: це карта для твого майбутнього вибору. Обов'язковість визначається вимогами лабораторної та бажаною поведінкою, а не кількістю рядків.

| Частина | Що забезпечує | Наскільки потрібна для простого сайту |
|---|---|---|
| Пошук меню, відкриття/закриття, обробник бургера | Поточне JS-меню взагалі працює. | Потрібне для нинішнього способу реалізації. Для CSS-only меню спершу потрібна інша HTML/CSS-структура. |
| Оновлення aria-expanded | Стан кнопки для доступності та її вигляд у поточному CSS. | Доцільно зберігати при JS-кнопці; це не лише косметика. |
| Закриття після посилання | Панель не перекриває секцію після переходу. | Невелика й корисна зручність. |
| Escape та повернення фокуса | Клавіатурне закриття. | Корисна доступність; технічно відкрити/закрити мишею можна й без неї. |
| Клік зовні | Додатковий спосіб закриття. | Додаткова зручність, не основа роботи бургера. |
| Resize понад 900 | Не переносити відкритий стан між розкладками. | Обробка зміни ширини, не потрібна для одного кліку на незмінному екрані. |
| data-src, loaded, observer, nearby | Відкладене завантаження й контроль за положенням відео. | Оптимізація; найбільше ускладнення порівняно зі звичайним HTML-відео. |
| document.hidden та visibilitychange | Пауза на прихованій вкладці. | Додаткова економія ресурсів. |
| matchMedia та change | Програмне дотримання налаштувань руху. | Корисне для фонового відео. Одного приховування CSS недостатньо, щоб гарантувати паузу відтворення. |
| Play/Pause, userPaused, події playing/pause | Доступне ручне керування та збереження паузи. | Для автоматичного рухомого фону доцільний спосіб його зупинити; альтернатива — стандартні video controls. |
| Promise catch та error | Реакція на невдалий запуск/помилку video. | Допоміжна обробка, частково необхідна для акуратної роботи з асинхронним play. |
| Submit демоформи | Зупиняє недоречний POST і чесно пояснює результат. | Потрібне для нинішньої демоповедінки; не є справжнім відправленням форми. |

### Що може працювати взагалі без цього файла

Текст, картки, таблиця, фото, стилі, hover, адаптивність і звичайні якорі продовжать працювати. Поля `required`, перевірка `type="email"`, підписи, select та автозаповнення також забезпечуються браузером і HTML.

Але просте видалення main.js зараз змінить три речі:

1. Мобільна кнопка не відкриватиме приховане CSS-меню. Потрібна CSS-only реалізація або інший спосіб показу навігації.
2. MP4 не підключиться, бо адреса лише в data-src. Залишиться постер, кнопка керування не з'явиться. Для простого HTML-відтворення треба змінити саме джерело й продумати керування та рух.
3. Валідна форма не показуватиме демостатус і може спробувати стандартне надсилання на свою action-адресу. Вбудована перевірка полів залишиться. Для справжньої HTML-форми потрібен справжній приймач; для статичної демонстрації треба обрати іншу чесну поведінку.

### Які місця можна пояснити простіше, не змінюючи поведінку

- Тернарний оператор у рядку 27 можна переписати як if/else: рядків стане більше, але початківцю може бути зрозуміліше.
- Назву loaded краще читати як «джерело підключене», а не «файл повністю завантажений».
- `.header` можна знайти один раз замість пошуку при кожному кліку.
- `var` можна замінити на const/let з урахуванням того, які змінні переприсвоюються. Це стиль та явність наміру, а не видалення можливостей.
- Захист від відсутнього source і точніша обробка його помилок — покращення надійності, але вони додадуть код, а не скоротять його.
- Порожній catch приховує деталі відмови. При навчанні корисно усвідомлювати причину; не треба сприймати його як виправлення будь-якої помилки.
- Брейкпоінт 900 дублюється в CSS і JS. Його потрібно тримати узгодженим, поки існує цей resize-обробник.

Для лабораторної зі строгими обмеженнями головне — вибрати потрібні можливості. Не варто скорочувати файл простим злиттям усіх інструкцій в один рядок: логіка й вимоги залишаться ті самі, а читати буде важче. Після цього розбору можна окремо визначити: який спосіб меню залишити, чи потрібне відкладене відео, які додаткові закриття потрібні та яку роль має демоформа.

## 8. Питання для перевірки розуміння

1. Чому в `addEventListener('click', closeNav)` немає дужок після closeNav?
2. Чим `toggle.hidden = false` відрізняється від `toggle.setAttribute('aria-expanded', 'false')`?
3. Чому return після video.pause важливий?
4. Чи означає loaded = true, що MP4 уже завантажився повністю?
5. Чому paused й userPaused не дублюють одне одного?
6. Що саме означають 100px у rootMargin?
7. Чому поля можуть перевірятися без JS, а поточна форма без нього все одно не стане сервісом надсилання?

Відповіді містяться у відповідних рядках розбору. Це перевірка логіки, а не потреба заучувати всі назви методів напам'ять.
